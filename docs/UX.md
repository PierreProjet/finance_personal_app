# UX — Finance Foyer

## Principes

- Une action financière importante doit être explicite et réversible quand c'est possible.
- Les informations sensibles sont séparées des préférences d'interface.
- Le dashboard privilégie les tendances, variations et historiques plutôt qu'un simple tableau de soldes.
- Les projections affichent leurs hypothèses et ne sont jamais présentées comme des garanties.

## Navigation

La barre latérale regroupe : Vue d'ensemble, Patrimoine, Comptes, Transactions, Budget et Analyses. Le bouton Paramètres ouvre un volet latéral sans quitter la page courante.

## Création d'un compte

Le modèle métier distingue la nature du compte, son usage personnel/foyer, son établissement, son solde et ses notes. L'interface doit progressivement évoluer vers un assistant en étapes afin que l'utilisateur n'ait pas à connaître les enums internes.

## Compte détaillé

Un compte doit permettre :

- modification ;
- suppression avec confirmation ;
- archivage ;
- note ;
- historique des soldes ;
- historique des opérations ;
- performance lorsque des positions d'investissement sont associées.

## Dashboard

Les widgets sont conçus pour être activables/désactivables depuis les préférences. Les graphiques utilisent des données historiques locales et restent fonctionnels sans service externe.
